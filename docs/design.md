# 工作耗时引擎设计

`@dvi-lab/work-time` 的输入契约见[最终角色属性与游戏文件契约](final-character-contract.md)。角色最终属性、可信游戏文件、任务目标为输入，所有任务派生量由库计算。公共 API 与单位见根[README](../README.md)。

## 模块边界

- `src/index.js`：浏览器可打包主出口。
- `src/effective-engine.js`：最终等级／速度、风险、品质、升级、材料产物、目标次数和完整时间；不重建装备／精通／药水。
- `src/game-file.js`：独立 Node 构建入口，Acorn/eslint-scope 解析可信游戏文件并生成最小声明闭包 ESM；提取过程中收集每项能力的诊断，构建脚本输出警告；编译不执行输入，不自行联网。详见[预处理诊断](game-file-check.md)。生成模块的正常 import 会执行选中声明，非安全沙箱。
- `src/adapter.js`：只在实际使用分支检查必要能力，错误附功能／能力；版本和摘要不作准入条件。
- `src/batch-time.js`：共享 v3 路径／容量／相位。新入口注入最终 movement 解析；内部旧规则路径保留原移动计算，用于回归对照。
- `src/gathering-pack.js`：计算采集的期望装包格数和每批有效尝试次数。
- `src/boss-feed.js`：投喂分段规则、首领补料路线、稳定循环速率及分项结果。
- `src/rule-engine.js`、`src/work-expectation.js`：内部0.1参考路径，不另增公开兼容入口。
- `src/domain.js`：冻结的采集技能／工具槽位。

运行入口不导入 Node 或解析器，不读取存档、网络、行情、页面或角色连接。消费工程负责可信文件加载与最终角色快照，构建时生成和打包游戏声明。包本身不带运行游戏资源。

## 行为与错误

输入快照不随任务推进。普通速度与升级速度分开；任务等级修正由模块结合游戏系数计算；所有普通工作统一按最终等级和速度计算。材料每次尝试消耗；游戏先判烧毁，再判被抓，再生成主产物／bonus。缺省字段不静默补零／一。多分支升级要求明确输入物品，物品编码、升级结果及额外材料依赖游戏规则。

能力检查跟随实际分支。缺少可用品质不阻断纯时间；缺少升级规则不阻断普通配方；物流缺失保留已知工作时间。来源 SHA／版本仅追溯；能力存在仍不能证明未来游戏机制符合模型，新机制需要新样例。

物流固定主城仓库起终点、空包出发、每批存仓、最后回仓。采集丢弃、偷窃及升级跳过物流。实例独立缓存路线，路径逐段取整，以有限周期处理大数量。模型使用当前等级、药水、速度和概率快照。

### 采集随机掉落占包

保留产物的无材料采矿、钓鱼和伐木按主产物及各品质、配方副产物、不同副本钥匙和技能宠物的占包估算周转。金币进钱包，直接进仓的坐骑和箱子不计格数。钥匙基础刻数使用配方和角色等级对应的经验，掉率使用生效的稀有倍率及最终钥匙倍率。技能宠物有空格时进包并占一格，满包时直接进仓。若配方有风险，烧毁副产物尝试入包，主产物、配方额外掉落、宠物和钥匙只在成功时判定。 1.0.1227 核验的适用配方每次产出一件不可堆叠主产物。

每趟从空包开始。不可堆叠物品按每次尝试的期望数量累计。可堆叠物品按编码 ID 合并各产出来源，首件占一格，尝试 `n` 次后的占格概率为 `1-(1-p)^n`。用单调搜索找到期望装包格数达到容量的位置。

有效批量有小数时，每趟独立按相邻的整数批量建模，两种批量的概率使平均批量等于有效批量。最多 128 趟的任务用二项分布计算还需下一趟的概率，以同一概率累计往返、步行和启动开销。更长任务用平均批量和最后一趟平均剩余量估算完整往返开销。 切换到近似计算时，以精确计算边界的趟数和步行开销为下限。这个模型近似随机装满的时点。全为堆叠物且恰好能填满时，以最慢到货的堆叠估计装满时间。产量和材料期望沿用原规则。

## 历史资料与验证

`tests/fixtures/work-time-baseline/buddy/` 与 origin.json 为只读原证据。25文件保留 raw 和 UTF-8/LF 摘要，Git `-text` 保留原始字节。原完整 bundle 未复制，origin 中 Lab 路径仅为当时核验语境，不是运行或CI依赖。旧 runner/oracle/归档器只保存，不递归执行。

新增耗时样本以原生过程的离线回放为基准。回放脚本从命令行接收原始游戏快照，共用摘要校验和原生声明提取，用同一资源版本、角色配置和任务对照估算。采集与制造按指定次数计量，统一从主城仓库出发，完成后回仓。技能首领以原生投喂动作和稳定补料循环计量纯投喂与物流。报告保存资源摘要、角色条件、任务、种子和逐次结果，新增样本与冻结历史分开存放。

内部历史入口复跑全部 14,950 条冻结物流向量。公共入口用隔离了随机掉落的配方复跑同一组向量，另用原生采集过程和回归用例验证随机掉落占包。隔离打包测试实际安装和调用两个公开入口，解析依赖从已安装 lockfile 包制成本地tarball预置，离线不需兄弟repo。npm test 显式列四个文件以兼容 Node20 Windows shell。历史数据不因新测试而重写。

npm 包白名单仅 src、README、LICENSE及自动包含的 package.json。MIT 适用于本包代码，不承诺扩展游戏资源权利。[本轮实际结果与限制](verification.md)。

## 生活 Boss 投喂

`estimateBossFeedRate({character, task: {bossId, itemId}})` 使用独立模型。`itemId` 为带品质的整数游戏 ID。`character.skills` 提供参与门槛及对应技能最终等级、速度。农耕作物使用包含投喂生效副手的最终倍率。`character.movement` 使用该动作生效的移动值与有效格数。

逐段判定成功率。普通物品先按配方等级修正和最终速度计算每 Tick 的基础成功率，农耕作物用专用时间与最终速度。再应用分段数与每 Tick 上限，完整一件的期望 Tick 数为分段数除以每段成功率。

补料循环从投喂站前往首领取料点，再到轮换后的投喂站。各段移动分别向上取整，补料和动作切换计入固定交互 Tick。单种可堆叠物品有至少两格可用时可一次取出全部同品质存货，平均物流趋近于零。只有一格可用时每次取一件。有限容量物品按每次可取件数折算物流。路线使用匿名站位序列，首选客户端预览使用的代表站位组。首次到场和阶段间等待在稳定循环之外。`secondsPerItemRange` 统计至少两条可计算路线的范围，并给出 `knownRoutes` 和 `routeCount`。混合路线只有各类站位齐备时才计入。代表路线不可用时，保留可用范围，综合单值和件/时留空。

状态包括 `ok`、`ineligibleItem`、`levelTooLow`、`unreachable` 和 `unknownTime`。缺少角色或游戏能力时以 `reason` 指出缺项，有独立依据的分项仍返回。错误格式的任务参数抛错。来源 `source` 取编译游戏文件的版本和摘要。

构建入口可从语义化导出或经核对的压缩符号提取 `bosses`、`bossUnlockLevel`、`bossFeedRecipe`、`bossFeedParts`、`bossUsesFarmingSpeed`、五个首领的 `boss*Layout`，以及现有的物品编码、步行和地图能力。投喂能力按需提取，普通配方可独立使用。耗时模型与工具页的贡献、经验、行情和百箱成本相互独立。

见[投喂离线回放与测试服标称](boss-feed-verification.md)。
